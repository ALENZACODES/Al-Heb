# Cantillation (trope) data

Generated by `tools/corpus/trope.mjs` (run `node tools/corpus/trope.mjs`). Outputs: `data/corpus/trope/table.json` (mark table), `data/corpus/trope/priestly-blessing.json` (Numbers 6:22-27), `data/corpus/trope/shema.json` (Deuteronomy 6:4-9), and the reader files `data/corpus/reader/*.json` (stage 3). `tests/corpus.trope.test.js` rebuilds all of it from the committed snapshot and checks it is unchanged.

**Scope and honesty.** This is a machine parse of the Unicode cantillation code points in the UXLC text (Tanach.us; copy without restriction). It names marks and their grammatical class; it says nothing about melodies, and no cantor, rabbi or Hebrew teacher has reviewed it. The app still does not teach trope (see `data/torahread/trope.json`); this data is groundwork for a future verse reader with audio.

## 1. Source text

Raw verse strings come from `data/corpus/source-snapshot.json` (items `bless-priestly-intro` (6:22-23), `bless-priestly-1..3` (6:24-26), `bless-priestly-close` (6:27), `shema-vahavta`; UXLC 2.6, file dated 19 Oct 2026, fetched 2026-11-03). When the gitignored XML cache `tools/vocab/.cache/tanach/` is on disk, the builder re-reads the verses from it and stops if they differ (`checkedAgainstXml: true` in the output means that check ran). The builder fetches nothing from the network; no text beyond those twelve verses was added to the repo. `bless-priestly-intro` and `bless-priestly-close` are snapshot-only (no registry record) and were fetched with `src/corpus/tools/fetch_sources_qere.py`. The fetchers read `<w>` words and the pointed `<q>` (qere) reading of a ketiv/qere pair and skip `<k>` (ketiv), the same convention as `src/torahread/tools/build-data.mjs`; none of these twelve verses contains a ketiv/qere pair.

## 2. The two naming systems

The marks are one set of signs with two common sets of names: **Ashkenazi** (the names most English-language primers use) and **Sephardi/Mizrahi**. The table gives both. Levels group the disjunctives by strength in the usual teaching scheme (1 emperors, 2 kings, 3 dukes, 4 counts); that grouping is a teaching convention, not part of the Masoretic text. Hebrew names are unpointed, as commonly printed. Numbers and Deuteronomy use the prose system of the 21 books; the poetic system of Psalms, Proverbs and Job (section 3) is listed only so its code points are accounted for.

### Parser rules that are not a plain lookup

- **U+05BD** is both meteg and siluk in Unicode. On the last word of a verse (the word carrying sof pasuq), the last U+05BD in that word is read as **siluk** (disjunctive, level 1); every other U+05BD is **meteg** (class `secondary-stress`, not a trope). Example: וִֽיחֻנֶּֽךָּ (Num 6:25) carries a meteg on the vav and the siluk on the nun.
- **U+05C0 paseq** is written by UXLC as a separate token "׀" after a space; the parser attaches it to the preceding word (`pasek: true`). When that word also carries munach (U+05A3) the pair is recorded as **legarmeh** (disjunctive, level 4). None of the three paseqs in these passages follows a munach (they follow darga, mahpach and mercha), so all three are plain separators.
- **Doubled postpositive/prepositive marks.** Pashta sits on the last letter; when the stress is not on the last syllable UXLC prints it twice and the copy away from the last letter marks the stress. Both copies are listed; the stress copy has `role: "stress"`, the edge copy `role: "mark"`. Example: בְּבֵיתֶ֙ךָ֙ (Deut 6:7). The same rule applies to segol, zarqa, telisha and yetiv, none of which occur here.
- **Stress.** `stressLetterIndex` is the 0-based index of the letter under an impositive trope, or of the stress copy of a doubled mark. It is `null` when the word has no trope (a maqaf-joined proclitic such as בְּכָל־) or only a single postpositive mark (פָּנָיו֙ in Num 6:26: the stress is on the last syllable, but the parser does not syllabify, so it does not name the letter).
- **Halves.** Each verse records `halves`: the word range up to and including the etnachta, and the rest. Numbers 6:23 and 6:27 have an etnachta (two halves); 6:22 and 6:24-26 do not (one half each). Deuteronomy 6:4, 5, 7 and 8 have one, 6:6 and 6:9 do not.

## 5. Record shape

```
passage { schema, id, ref, system, source, sourceUrl, license, attribution, checkedAgainstXml, registryIds, markCounts, words, verses[] }
verse   { book, chapter, verse, ref, raw (with trope, markup stripped), he (registry normalisation, no trope), largeLetters, words[], halves, markCounts }
word    { i, text, plain, letters, marks[], trope, tropeClass, disjunctiveLevel, stressLetterIndex, pasek, sofPasuk }
mark    { id, unicode, unicodeName, char, ashkenazi, sephardi, cls, level, placement, at (code-point offset in the word), letterIndex, letter, role?, doubled? }
```

## 6. Reader data (stage 3)

`data/corpus/reader/priestly-blessing.json` and `shema.json` (`schema: alef-corpus-reader/1`), one object per passage:

- `verses[]`: `he` (no trope, equals the registry line), `heTrope`, JPS 1917 English (Sefaria "Public Domain" label, unverified), `unit` (reading unit id), `halves`, `words[]`, `tokens[]`, and `timing {start: null, end: null}`.
- `words[]` are UXLC word units: a maqaf-joined proclitic is its own word with `joinedWithNext: true` and no trope. `tokens[]` join maqaf groups (the registry's `wordsOf` convention); the literal glosses from the registry (`wordGlosses` on `bless-priestly-1..3` and `shema-1`) attach to tokens, so Numbers 6:22-23, 6:27 and Deuteronomy 6:5-9 have `gloss: null`; `registryVerses` lists the verses a registry record covers. Joining each verse's tokens with spaces plus a sof pasuq reproduces the registry `he` exactly (tested).
- Every word, token and verse carries `timing.start` / `timing.end` = `null`: placeholders in seconds for future audio alignment. No recording exists.
- `pauseAfter`: `major` after a level-1 disjunctive (etnachta, siluk), `minor` after any other disjunctive, `pasek` after a paseq on a conjunctive word, else `none`.
- `wordIndex`: plain word -> list of [verse, word index] occurrences (32 distinct forms in the blessing passage, 42 in the Shema passage).
- `aliyah`: parashah (Nasso 35 / Vaetchanan 45, the numbering of `data/calendar/parsha.json`), the seven aliyah ranges plus maftir as listed by the Sefaria calendar API (fetched 2026-11-04 for 2026-05-30 and 2026-07-25, diaspora), which aliyah holds the passage (Numbers 6:22-27 sits inside the 4th, 5:11-6:27; Deuteronomy 6:4-9 opens the 6th, 6:4-6:25) and whether the passage starts it.
- `readingUnits`: liturgical splits (blessing: an introduction unit for 6:22-23, one unit each for 6:24, 6:25, 6:26 with 3/5/7 words, and a closing unit for 6:27; Shema: verse 4 alone, then verses 5-9). Common practice, not reviewed by clergy.
