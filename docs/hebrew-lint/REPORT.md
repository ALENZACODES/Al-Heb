# Hebrew lint report

Generated by `node tools/hebrew-lint/cli.mjs --report`. The linter only reports; it changes no data.

**Passing this linter is NOT proof of correct Hebrew.** It checks code points and spacing only. It cannot detect wrong words, misspellings, wrong vowels that are validly placed, wrong grammar, wrong translation, or bad transliteration. Native review is still required.

Scanned 460 JSON files under data/ (242197 strings containing Hebrew, including object keys). Unparseable files: 0.

## Canonical mark order

Marks on one letter must follow Unicode canonical order (the order NFC produces): letter, vowels (sheva through qubuts), dagesh/mapiq, meteg, rafe, shin/sin dot, then cantillation by combining class. This matches the repo normalisation test. It is the opposite of "dot first" orderings some fonts tutorials show, so a string typed dot-first is reported by mark-order.

## Reading the numbers

- `data/photo/_benchmark/*` holds raw OCR engine output, which is malformed on purpose; its findings are expected and not data bugs.
- `data/corpus/source-snapshot.json` keeps source text as received (shin/sin dot before vowel, HTML-like tags, cantillation); the runtime pipeline normalises it, so its mark-order count is a property of the snapshot, not of displayed text.
- Isolated marks shown as specimens (alone, in parentheses, or after a dotted circle) are not flagged as stray.
- Fragment fields (syllables, marked segments, folded dropTokens) are exempt from nonfinal-letter-at-end by path.
- Counts are per finding, not per string; one string can raise several.
