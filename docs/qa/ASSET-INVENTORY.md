## 10. Safe actions

Nothing in this task deletes or moves an asset. These are candidates for a later, reviewed change; each keeps references and provenance intact and none removes a whole category.

1. Use the status table (section 3) as the map of what is live. `assets/img/gen/` is deployed but hidden until images are approved; do not prune it by size before the approval pass decides which ids stay. When ids are rejected, move their files to an underscore-prefixed folder (skipped by the build) only in the same change that updates `data/img/index.json` and the `data/images/*.csv` rows, and keep the CSV row and the `data/images/provenance.json` entry.
2. Byte-identical duplicates (6a): keep one canonical file per group and repoint references first (the CSV `ref_files` column lists where each is named). Start with groups inside one category; do not touch a group that spans a deployed and a repo-only copy until the deployed path is confirmed unused.
3. Retired-concept art (section 8): do not delete. Mark the affected ids rejected in the approvals/review notes so they cannot be approved by accident, keep the files and prompts for provenance, and regenerate from the current chain idea. Separately, gate the app text that still prints the old story (the source lines listed in section 8).
4. Placeholders: they are rebuilt from `data/images/prompt-groups.json` by `tools/images/make_placeholders.mjs`. Where a placeholder has a generated image of the same stem and no book or app reference, it is a candidate to stop shipping in `assets/` (in the build, not out of git). Keep the folder for stems with no generated image.
5. Repo-only images (QA screenshots, fixtures, reference images) cost no learner bytes; shrinking them is optional hygiene. Before touching a `docs/qa/` shot, search the `.md` files for its name.
6. Fix every row in section 7 first: a broken path costs a learner a failed request, whereas an unused file costs nothing at runtime.
7. Before any removal: run the unit tests and `node tools/meta/scan.mjs --text`, re-run this tool, and check that the CSV diff shows only the intended rows. Regenerate `precache-manifest.js` only through its build tool, never by hand.

## 11. Method and limits

- Scope: tracked files only (`git ls-files`); untracked or ignored files (for example `dist/`, `data/images/sheets/`) are not counted.
- Image dimensions were not measured (no image decoder is used); sizes are bytes on disk.
- Text scanned for references: 2108 tracked text files, each up to 6 MB. Reference by stem (assets/img ids) is a token match and can over-count where an id appears in prose; name-only matches are in the CSV (`ref_weak_name`) and not used in the tables.
- "Shown to learners" follows the resolver rules and the approvals file; a screen that bypasses the resolver would not be seen by this tool.
- Duplicate detection is exact (sha256); visually similar pictures are not detected.
