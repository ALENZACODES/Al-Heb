### Batch 1 (2026-11-04 ~20:10). Ranked by learner impact per effort. "v0?" = fits the rule "v0 stays 15 routes, rest is preview tier".

Verified-by-me facts used below (checked 2026-11-04 on the sources named): ts-fsrs 6.0.0 is MIT on npm and in its repo LICENSE, depends on one package (srs-kit 1.0.0, BSD-3-Clause), builds with node >= 24 (npm registry); ALEF `src/curriculum/srs.js` header says it is NOT the reference FSRS, uses hand-chosen constants and was never fitted; ALEF vocab (`data/vocab/words.json`, 6,303 rows): 1,820 verbs, 1,817 with a binyan, only 501 verbs with a root, 997 distinct roots, 151 roots with 3 or more words, verb `forms` keys are only present / future / infinitive / feminine / plural (no past tense), every row `proofread` null.

**R-001 Replace the invented "FSRS-style" scheduler with the real FSRS (vendored ts-fsrs ESM build).**
- What: add a thin adapter so `src/curriculum/srs.js` callers (`actions.js`, `checkpoint.js`, `progress.js`, `lesson.view.js`, `learn.view.js`) get reference FSRS-6 scheduling; migrate stored cards (stability/difficulty/due) without losing them; keep ALEF's own card kinds and the 10-minute Again step.
- Why: the file header itself says scheduling quality was never tested and constants are ours. The gameplan's "20-30% fewer reviews than SM-2" comes from secondary summaries (mindomax, rhythmword) that I did not verify; ALEF has zero review history, so it cannot be measured here. The honest value is "uses the published, community-tested algorithm", not a saving figure.
- Pillar: all (review engine). Effort: S-M (adapter + migration + fixture test). 
- Licence/sale risk: MIT + BSD-3 for the dependency; keep both notices in /credits. Low. Note ts-fsrs ships as built ESM; vendor the `dist/index.mjs` file only (no build step needed at runtime, no npm install in the repo).
- v0?: yes, it changes the engine behind the existing review route; no new route.
- Acceptance: a fixture of 30 (rating, elapsed-days) sequences produces the same stability/difficulty/interval as the vendored library's own output to 1e-6, AND a stored v-old card set loads, is migrated once, and keeps its due dates within one day.

**R-002 Root families on the word and lesson screens ("same root, new word").**

- Pillar: 2. Effort: S. Licence: none (own data; roots came from Wiktionary per `source.dictionary`, CC BY-SA 4.0 per Wiktionary:Copyrights; keep attribution on /credits). v0?: the strip may sit inside the existing word/review screens (no new route); a dedicated "roots" browser is preview.

- Caveat for B: root coverage is 27% of verbs; the first deliverable should also report the coverage number on screen or in the build log, not claim "roots taught".

### R audit round 1 (clock 20:14). Correction: the "~20:35" and "~20:45" labels on my earlier entries were estimates; the real clock was about 20:10 to 20:13.
Basis: B-a1 (nikkud fade: src/nikkudfade, tools/nikkudfade, tests/nikkudfade.test.js, data/nikkudfade) and B's roots lane (src/roots, tools/roots, data/roots, tests/roots.test.js), read and partly re-run by me (`node --test tests/nikkudfade.test.js` 14/14 pass; `node tools/nikkudfade/build.mjs --check` current). R-002, R-007, R-008 intent is met in structure.

**Main issue 1 (fix first): root families merge different roots that merely share consonants, and the drills then assert they are related.**
Root cause: B groups by the `root` string from the dictionary data ("a family is exactly the rows that share a root string"); the same three consonants can be several unrelated roots. Evidence from `data/roots/families.json` (my reading; I am not a native speaker, so treat as a flag for review, not a verdict): ע־ר־ב lists guarantee, pleasant, evening, mixture, raven, steppe and west as one family; ס־פ־ר lists story, counting, number and literature together with scissors and "to get a haircut" (a different sense of the consonants); ח־ל־ל lists window, desecrate, secular, challah and "far be it". The draft banner says "some links may be loose", but the quiz prompt is `Which word comes from the root X?` (model.js) and `Same root as ..., which verb?`, which states a fact the data cannot back.
- Fix (small): in prompts and headings say "words that share the letters X" until a native reader has marked a family "one root"; add a per-family `verified` flag (default false) and only build the `root` and `newbinyan` drills from verified families; add the 5 largest families to the native-review pack first.
- Acceptance: no screen or prompt says "comes from the root" for an unverified family; test fails if a drill is generated from a family without `verified: true`.

**Main issue 2: the nikkud "look-alike" flag is too generous, so stage 2 is nearly stage 1 for 42% of the set.**
Root cause: `ambiguous` counts any other entry with the same letters and different points among the 5,000 most frequent words. Evidence: 100 of 240 items flagged. The rival words behind the flag are often rare: הוּא is flagged because of הֱוֵא (rank 4354), אֲנִי because of אֳנִי "fleet" (rank 1236), כֵּן because of כַּן "pedestal" (rank 1234), עַל because of עֹל "yoke" (rank 303 is the only close one). If the rival must be within rank 1000 the flagged count falls to 53; within 1500 to 66; within 2000 to 74 (my recount from words.json, same method).
- Fix (small): add a rival-rank cap to the builder (start at 1500 and document it) and report the flagged count in the build output.
- Acceptance: `build.mjs --check` passes, flagged count is stated in the file note, and a test pins that no flagged item's only rival has rank above the cap.

**Main issue 3: nothing a v0 learner touches reads the engine, and the word set ignores where the learner is.**
Root cause: items are the 240 most frequent modern words, not words the learner has met; `unlockLesson` of the items runs r01 to r30 (34 from r24), and only 58 of 240 sit in the v0 path r01 to r10. A first-week learner is asked to read words from lesson 24 with points fading. R-007 (put the stage on the existing review card) is not met; the new route is a separate preview page. Acceptable for a first slice, but the build log should not call pillar 1 done.
- Fix (S): filter `pickSession` items to `unlockLesson <= learner's current lesson` using the progress state the Today card already reads; keep the full list for a "practice any" toggle.
- Acceptance: with progress at r03, no session item has `unlockLesson` later than r03.

**Main issue 4 (evidence thin): stage movement rests on self-reports, so the "fade" can advance on nothing.**
"I read it" is not checked; a learner can tap through and reach stage 3. Because B's data has a transliteration for every item, a checkable version is cheap: after the word is shown, offer 3 sounds-like options (the right one plus the rival's sound for flagged look-alikes) and count a read as unaided only if the choice is right. This keeps "no audio needed" and gives real signal on exactly the look-alike case the gameplan cares about.
- Acceptance: a wrong choice records an aided read; a test with a fixed seed shows the rival's sound among the options for a flagged item.

**Smaller points.** (a) The first items include אֵת, glossed "used to introduce a semantically definite direct object": a poor first reading word and a long gloss for a phone card; M's rank-based sort needs a "teachable first" filter. (b) 114 of 240 items are verbs in dictionary form; fine, but the page cannot show a verb's family yet; link each verb item to its roots page when B's roots lane has a verified family. (c) Both lanes copy `rng`/helpers rather than import; M already flagged this, I agree it is minor.
