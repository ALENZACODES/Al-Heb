# Local TTS factory for synthetic clips (Israeli from Hebrew; Sephardi and Ashkenazi from respellings)

Status: the pipeline is built and its plumbing is tested in `--mock` mode. **No real audio has been generated by it yet, nobody has listened to anything, and the quality of respelled Sephardi and Ashkenazi speech is unknown.** To run it for real on your own GPU computer, follow `docs/tts/RUN-ON-YOUR-PC.md` (exact commands, order, a 20-clip listening checklist per tradition, how to copy results back).

Sephardi and Ashkenazi clips can also be made with an outside voice service (man and woman voices, REST calls, three machine judges, a hand-off folder for a listener): see `docs/tts/VOICE-SERVICE-RUNBOOK.md`. That path has only been run in mock mode.

What it does: turns the audio manifest into a render plan, renders clips on your own machine with an open-weights model, polishes them, runs an automatic acceptance gate, and marks only the accepted clips in the manifest as synthetic and unreviewed (`status: "synthetic-unreviewed"`). The model speaks Israeli Hebrew natively only. So:

- **Israeli** clips speak the pointed Hebrew with language token `he` (`source: "tts-hebrew"`).
- **Sephardi and Ashkenazi** clips speak a "sound word", a Latin-letter respelling of the Hebrew made by `tools/tts/soundtext.mjs` (see `docs/tts/SOUNDWORDS.md`), with a configured language token (default `es`) (`source: "tts-respelled"`). This is an experiment: whether the model reads those respellings as Sephardi or Ashkenazi Hebrew is untested. These traditions are opt-in (`plan.mjs --tradition sephardi`), because nobody has listened.
- Letters, vowels and syllables are never synthesised in any tradition: they stay human-only.

## What goes where

| Step | Tool | Input | Output |
|---|---|---|---|
| 1 plan | `tools/tts/plan.mjs` (`--israeli-only`, `--tradition`, `--confidence high\|all`, `--lang-tokens`, `--voice`, `--limit`) | `data/audio/manifest*.json`, `data/vocab/deck-order.json`, `data/vocab/frequency.json`, `tools/tts/soundtext.mjs` | `tools/tts/plan.json` (each item: clip id, tradition, voice, text to speak, language token, source, sound word, confidence), `tools/tts/donor-export/human-only-<tradition>-<voice>.csv` |
| 2 render | `tools/tts/render_chatterbox.py` | `plan.json`, reference WAVs for the m and f voices | `<work>/raw/<voice>/<tradition>/<kind>/<id>.wav`, and `<work>/render-log.jsonl` (source, sound word, language token, model name and version, reference-voice digest per clip) |
| 3 post | `tools/tts/post.mjs` | the WAVs | `<work>/mp3/audio/<voice>/<tradition>/<kind>/<id>.mp3` |
| 4 verify | `tools/tts/verify.py` | the MP3s | `tools/tts/verify-report.csv` |
| 5 mark | `tools/tts/manifest_update.mjs` | the report, the MP3s, `render-log.jsonl` | copies accepted MP3s to `audio/`, writes `<clip>.mp3.meta.json`, sets `status: "synthetic-unreviewed"`, `source` and a `synth` record in the manifest |
| 0 preflight | `tools/tts/preflight.mjs` | this computer | a GO / GO WITH WARNINGS / NO-GO report (disk, RAM, GPU, Python, torch, packages, model files, ffmpeg, reference WAVs); changes nothing. `--mock <preset>` pretends to be another computer, for tests |
| all | `tools/tts/run_all.sh` | | runs 1 to 5; passes `--israeli-only`, `--max-clips`, `--resume`, `--tradition`, `--confidence`, `--voice`, `--lang-tokens`; `--mock --root <scratch copy>` for a dry run (it refuses `--mock` without `--root`) |

`<work>` is `$ALEF_TTS_WORK` or `~/alef-tts-work`. It is outside the repo on purpose (raw WAV is large).

Order inside the plan: by tradition (Israeli, Sephardi, Ashkenazi), then confidence (high first), then the priority tiers below. For Sephardi and Ashkenazi, confidence is the respelling engine's own rating of its sound word. For Israeli it only says the Hebrew text has vowel points; it says nothing about how the speech will sound.

Priority order in the plan: tier 1 core prayer lines (same list as the human-recording priority subset), tier 2 words in `deck-order.json` (by position), tier 3 words or lines found in `frequency.json` (by corpus rank), tier 4 the rest. Plan sizes change as the manifest changes; re-run `plan.mjs` for current numbers (the last check, with `--tradition all`, planned about 21,400 clips across both voices, of which about 10,300 were high confidence). Entries that already have a file (human or synthetic) are never planned.

## Install (your machine)

You need: Python 3.10 or newer (3.11 is the safe pick; versions were not tried here), Node 20+, ffmpeg and ffprobe on PATH.

```bash
python3.11 -m venv ~/alef-tts-venv && source ~/alef-tts-venv/bin/activate
pip install chatterbox-tts faster-whisper nakdimon      # nakdimon only if you need --vocalize
# NVIDIA GPU: install the CUDA build of torch first, per pytorch.org. Apple silicon: --device mps. CPU works, slowly.
```

Version note (verified from the fetched pages): the Chatterbox README on GitHub describes a "Multilingual V3" checkpoint selected with `t3_model="v3"`. The PyPI release `chatterbox-tts 0.1.7` inspected here only loads the v2 checkpoint (`t3_mtl23ls_v2.safetensors`). The renderer detects whether `from_pretrained` accepts `t3_model` and uses v3 if so, otherwise v2, and records which in `render-log.jsonl`. To get v3 you may need `pip install git+https://github.com/resemble-ai/chatterbox` (not tried).

### Voices

Chatterbox clones the voice in a reference WAV. Provide one for each of the two narrator voices (about 10 to 20 seconds of clean speech, no music):

```bash
--ref-m ~/voices/m.wav --ref-f ~/voices/f.wav
```

Use only a voice you own or a donor who signed `docs/voices/donor-rights-grant.md`. Do not clone any real person's voice without that grant. Without references the renderer refuses to run (both voices would sound the same) unless you pass `--allow-default-voice`; it also refuses when `--ref-m` and `--ref-f` are the same audio. The render log records a short digest of each reference file, not its name or path.

## Run

```bash
cd alef
node tools/tts/plan.mjs                                    # Israeli only; writes plan.json + donor-export/
node tools/tts/plan.mjs --tradition sephardi --confidence high   # opt-in, respelled; see RUN-ON-YOUR-PC.md
python3 tools/tts/render_chatterbox.py --limit 50 --ref-m ~/voices/m.wav --ref-f ~/voices/f.wav   # first 50 only
node tools/tts/post.mjs --limit 50
python3 tools/tts/verify.py
node tools/tts/manifest_update.mjs --dry-run               # then without --dry-run
node tools/audio/build_manifest.mjs --check                # must still say "manifest files are current"
```

Listen to a sample before scaling up. Follow `docs/voices/tts-evaluation-protocol.md` (native Hebrew listeners, blind, pointed vs unpointed). The gate below does not replace this.

Everything is resumable: re-running skips WAVs and MP3s that exist. Delete a file to redo it. Add `--vocalize` to the render step only if some plan text has no niqqud (Nakdimon adds it; the manifest text normally already has niqqud).

### Expected time (an estimate, not a measurement)

Not measured: no real model has run in the sandbox where this was built. A real-model attempt was made on 2026-11-04 and failed for resources, not for access: PyPI and Hugging Face were reachable (the Chatterbox weights file is about 2.1 GB), CPU torch installed, but `pip install chatterbox-tts faster-whisper` ran out of disk (about 11 GB free, 2 CPUs, 7 GB RAM, no GPU) after 6.5 minutes. Nothing was generated or transcribed. Chatterbox is a 0.5B-parameter model; on a recent NVIDIA GPU, short words are commonly a second or two each, so a few thousand clips would be a few hours. On CPU expect many seconds per clip, so a day or more for the full plan. Post-processing took roughly 1 to 2 s per clip on a slow 2-core sandbox; `post.mjs --jobs N` parallelises it. verify.py with Whisper large-v3 is fast on GPU and slow on CPU (use `--model small` to trade accuracy for speed, and expect more rejects).

## The acceptance gate

Respelled clips (Sephardi, Ashkenazi) are not transcribed: their target is a Latin-letter sound word, not Hebrew, so a Hebrew transcript cannot be compared with it. They are only checked for length, and the report marks them `gate=duration-only`. Passing means "not obviously broken", not "sounds right". The rest of this section describes the Israeli check.

`verify.py` transcribes each MP3 with faster-whisper (`large-v3`, language `he`), removes niqqud and punctuation from both target and transcript, folds final letters, ignores spaces, and computes character error rate. CER above 0.10, a clip under 0.2 s or over 20 s, or an empty transcript is rejected. Rejected clips are listed in `tools/tts/verify-report.csv` with the reason and are never marked.

The gate catches missing, truncated, repeated or wrong speech. It does **not** check vowels (the transcript has no niqqud), accent, stress or voice quality, and Whisper itself makes mistakes on short isolated words, so some good clips will be rejected and some bad ones accepted. Spot-check by ear.

## MP3 format and metadata

Mono, 44.1 kHz, 64 kbps CBR, loudness normalised in two passes to -16 LUFS integrated (true peak limit -1.5 dBTP), leading and trailing silence trimmed (about 50 and 80 ms kept). Metadata: `-map_metadata -1`, no ID3v1/v2, no Xing/Info header, bitexact flags. `post.mjs` then runs ffprobe on every output and rejects the file if any tag exists, if there is more than one stream, or if the channel count or rate is wrong. It also zeroes the encoder version string that libmp3lame writes into frame padding ("LAME3.100"); that is only done with `-reservoir 0`, and the script compares the decoded samples before and after and refuses the clip if they differ (checked on mock tones in this sandbox, not on speech).

One thing cannot and should not be stripped: Chatterbox embeds an inaudible neural watermark (Resemble's PerTh) in every output; its README says it survives MP3 compression. This is a machine-detectable "generated" marker and is consistent with labelling the clips as synthetic. Do not try to remove it.

## How the app labels these clips

`manifest_update.mjs` writes `status: "synthetic-unreviewed"`, `source: "tts-hebrew"` or `"tts-respelled"` (mock runs add `:mock`) and a `synth` record into the manifest entry (core file or word shard): `soundWord` and `soundModel` (respelled only), `languageToken`, `model`, `modelVersion`, `package`, `confidence`, `flags`, `gate`, `refDigest`. Tradition and voice are the entry's own fields. It also writes a sidecar `audio/.../<id>.mp3.meta.json` (the same status, source and `synth`, plus `reviewed: false`, `redistributionCleared: false`, CER, render time). `tools/audio/build_manifest.mjs` reads that sidecar, so a later rebuild gives the same bytes (checked on a scratch copy). The model name and version come from the renderer's `render-log.jsonl`; a clip with no record there is not marked. It never writes `"recorded"`, and never changes an entry that is `"recorded"` (a human clip) or `"synthetic-reviewed"`.

Statuses the app knows (`src/shell/audio-labels.js` is the one table): `recorded` ("Recorded by a human reader"), `tts` (older value, kept readable: "Synthetic voice (Israeli only), not a recorded teacher"), `synthetic-unreviewed`, `synthetic-reviewed`, `missing` ("No audio yet"). The two synthetic statuses read per tradition, for example "Synthetic voice (Sephardi style, made from a respelling; not a recorded teacher; unreviewed)" or "Synthetic voice (Israeli style, made from pointed Hebrew; not a recorded teacher; unreviewed)". The label names the tradition of the file that plays, not the learner's setting. `synthetic-reviewed` ("reviewed by a listener") exists in the table, but nothing sets it: a person would have to edit the sidecar and manifest by hand. Anything the table does not know counts as missing. `isSyntheticStatus` in that file is the check to use for "is this a computer voice"; do not compare with `'tts'`.

The browser's device voice stays Israeli-only (`DEVICE_LABEL` in `src/shell/audio-access.js`): a Sephardi or Ashkenazi learner with no clip gets "No audio yet".

Status naming history: an earlier version of this document kept the value `tts` and refused a new name, because `summarizeManifest`, `fileLabel`, `build_manifest.mjs` and `coverage.mjs` only knew `recorded` and `tts`, and an unknown status would have been labelled as a human recording. Those places, plus `src/shell/audio.js`, `src/speak/speak.js` and `tools/record-kit/ingest.mjs`, now all go through `isSyntheticStatus`, and `tests/audio.labels.test.js` and `tests/audio.access.test.js` check that no synthetic status is ever labelled or counted as human.

## Handing clips back

Same machine as the repo: `manifest_update.mjs` copies the accepted MP3s into `audio/` itself (it reads `<work>/render-log.jsonl` too). Then run `node tools/audio/build_manifest.mjs --check`, review, commit (this tool commits nothing), and run the precache build as your normal release step needs.

Different machine: zip `<work>/mp3`, `<work>/render-log.jsonl` (required: it holds each clip's provenance) and the verify report, unzip the MP3s into a scratch folder on the repo machine and run

```bash
node tools/tts/manifest_update.mjs --work <scratch-parent> --report <path>/verify-report.csv
```

where `<scratch-parent>/mp3/audio/...` holds the files (the tool looks for `<work>/mp3/<manifest path>`). For clips that come from an outside source (not this pipeline), use `tools/audio/ingest.mjs`; see `docs/audio/INGEST-CLIPS.md`.

Human-only work: `tools/tts/donor-export/human-only-<tradition>-<voice>.csv` uses the same columns as `docs/voices/recording/recordings_needed.csv`, so it can feed the existing donor sheet tooling (`tools/audio/recording_sheets.mjs` reads the priority subset of the same data).

## Tests

`node --test tests/tts.pipeline.test.js` runs plan, render, post, verify and manifest update end to end in `--mock` mode in a temporary directory: the original 20 Israeli clips (one with the wrong tone, which is rejected and stays `missing`), and a Sephardi plus Ashkenazi run using a small stub in place of `soundtext.mjs`. It asserts: 19 of 20 are marked `synthetic-unreviewed` with `source: "tts-hebrew:mock"`; respelled clips carry their sound word, language token and model fields and `source: "tts-respelled:mock"`; a pre-existing human `recorded` clip, an Israeli letter and a word with no sound word are untouched; a clip with no render-log record is not marked; a `synthetic-reviewed` clip is left alone; the renderer refuses Hebrew text for a respelled tradition, letters, vowels, syllables and a missing sound word; the `--tradition` and `--confidence` filters work in plan and render; the real renderer refuses the same reference audio for both voices; every MP3 passes the ffprobe metadata check; render and post are resumable; and the manifest is not touched without `--allow-mock`. A last test checks that the real `soundtext.mjs` plugs into the plan. Mock mode proves the plumbing and the gate logic only: the "voice" is a sine tone and the "transcription" reads the tone's frequency back to the text. It says nothing about Chatterbox, Whisper, the respellings or any tradition's sound. The file takes a minute or more in a slow 2-core sandbox.

`node --test tests/tts.preflight.test.js` checks the preflight verdict logic against pretend computers (`--mock`: ready, no disk, no Python, no torch, no GPU, CPU-only torch, no ffmpeg, small VRAM) and one real-probe smoke run. A mock GO says nothing about a real machine. The same pipeline test file also covers `--israeli-only`, `--max-clips`, `--resume` (crash leftovers, a torn log line) and the `synthetic-unreviewed` label on every render-log line, in mock mode.
