# First 100 clips to record, per tradition

Generated by `node tools/audio/first100.mjs --write` from `data/audio/manifest*.json`. Do not edit by hand. The exact filenames and Hebrew text are in `docs/voices/first-100.csv` (200 rows: 100 sephardi, 100 ashkenazi).

Status: **a plan, not a recording.** No audio exists in the repository yet. The picks are a draft by the tool author (value order below), not a product or teaching decision, and no teacher or cantor has reviewed the Hebrew text or the choice of clips. The pointed text is copied from the audio manifest unchanged.

## Filenames

Pattern, the same as the app's audio paths: `audio/<voice>/<tradition>/<kind>/<id>.<ext>`.

- The record page (`tools/record-kit/recorder.html`) writes `.wav` and builds these names itself. John does not have to type or rename anything.
- The app plays `.mp3`. Ingest makes the `.mp3` (trim, loudness, mono) and puts it in `audio/`. CSV columns `wav_m`/`mp3_m` are the man voice, `wav_f`/`mp3_f` the woman voice. Use the voice that matches the speaker; one speaker is one voice.
- `kind` is one of `letter`, `vowel`, `syllable`, `word`, `line`. Prayer lines use kind `line` (the manifest's `prayer` entries are optional aliases of `line`).
- Example (sephardi, man): `audio/m/sephardi/letter/shin.wav`, `audio/m/sephardi/word/shema-1-w1.wav`, `audio/m/sephardi/line/shema-1.wav`.

## How to record the batch

1. Build one page that holds both lists: `node tools/record-kit/build.mjs --script docs/voices/first-100.csv --out ~/first100.html`. (Passing `--tradition sephardi` embeds only that tradition.)
2. Open it with the tradition and voice in the link, which preselects and locks them so the page matches the list: `first100.html?tradition=sephardi&voice=m` (also `ashkenazi`, and `voice=f` for the woman voice). Without the parameters, pick them on the first screen (they must match the list). Tick the consent boxes, record the 100 in order. Re-record when the page warns about loudness or silence.
3. Press Export a zip. Dry run: `node tools/record-kit/ingest.mjs <zip>`. Apply: add `--apply`. Then listen to every clip before anything ships (ingest checks the technical quality only, not whether the reading is right for the tradition).
4. Reading brief: read as you would in your own congregation's tradition; sound every vocal shva; keep the same distance from the microphone throughout. See `docs/traditions/SEPHARDI-DECISION.md` for what differs between the Israeli, Sephardi and Ashkenazi readings (draft, unreviewed).

## Same text, other ids (record once, then copy)

Some lesson-word ids have exactly the same pointed text as a clip in the list. They are not in the 100, but each id has its own manifest entry, so each needs its own file or the app will still say "No audio yet" for that lesson word. `node tools/record-kit/ingest.mjs` does this: when it accepts a clip it also copies the MP3 under every other lesson-word id with the same voice, tradition and pointed text (a `.meta.json` with `copyOf`, manifest status `recorded` plus a `copyOf` field). The dry run lists the copies; `--no-copies` turns it off. The ids it covers for these 100 (it covers any other duplicates too):

| tradition | extra id | same text as (in the 100) |
|---|---|---|
| sephardi | `word/r04-w1` | `word/r02-w1` |
| sephardi | `word/r04-w2` | `word/r03-w1` |
