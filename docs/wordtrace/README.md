# Word tracing (src/wordtrace)

Status: DRAFT. Built and tested with synthetic input only (fake-DOM unit tests, Chromium with a scripted mouse drag at 390x844). No real finger or stylus, no phone, no teacher, no screen reader was used.

## Did word tracing exist?
No. Before this feature the app had single-letter tracing (`src/letters/trace.view.js`) and a printed workbook with "words" pages (`assets/workbook/*`, 3 pages of words per PDF), but nothing in the app where a learner draws a whole word. The requirement "practice drawing letters, then words, in print and cursive" was only half covered.

## What it does
`src/wordtrace/wordtrace.view.js` (`mount(root, ctx)`), route `#/words/trace`.
- A word is laid out right to left as letter cells (`dir="rtl"`; 2 letters = one row, 3 = one row, 4 = 2x2, 5-6 = 3 per row). Each cell is a real `createTracer()` from `src/letters/trace.js`, fed the unchanged `data/letters/letters.json` strokes (print or cursive). Only the active cell takes pointer input; finishing a cell activates the next.
- Fade-out guides per word attempt (round): solid outline -> dotted outline -> no guide. A clean round advances; a round with `MISS_LIMIT` (3) wrong strokes, or any stroke the tracer had to reveal, repeats the same guide. Tracing is finished after a clean no-guide round. "Skip to vowel marks" is always available.
- Niqqud step: choose a mark from a tray (the marks the word needs plus plausible wrong ones, max 6), tap the letter it belongs on, tap again to remove. Check scores each letter by exact set match (shin dot + kamatz on shin counts as one cell). Wrong cells are listed in text, not only colour. Shuruk is the dagesh on a vav. "Show the answer" counts as 0 correct.
- Final letters (sofit): final forms use their own stroke data; the cell is tagged "final form" with a one-line rule. Bank validation rejects a final form anywhere but last and a regular form at the end of a word (`sofitProblems`). A final form is offered when its regular form is known.
- Cursive: a visible note says connected handwriting between letters is NOT modelled. Letters are traced one by one in their cursive shape (ktav yad); joins are neither drawn nor checked.
- Levels: `two` (2-letter), `three` (3-letter), `prayer` (list-based: `data/pronunciation/prayerwords.json` plus 4-6 letter lesson words found in the siddur texts of `data/corpus/registry.json`; includes שָׁלוֹם). Levels are suggested (3 finished words), never locked.
- Eligibility: a word is offered only if all its letters were traced in the Letters screen (either script) or taught by a completed lesson (`curriculum.progress`). The tick box "Include letters I have not traced yet" lifts this. With nothing traced the screen says so and links to the letters.
- SRS hook: a missed word (rating 1 or 2) gets an SRS card `wordtrace:<script>:<pointed word>` in store key `wordtrace.cards`, scheduled with `src/curriculum/srs.js` (`newCard`/`review`). A clean pass only reviews an existing card. Due words are offered first. These cards are deliberately NOT written to `srs.cards`: `review.view.js` expects ids it can parse (`letter:`, `vowel:`, `word:<lesson>:<n>`...) and would not know how to show a traced word. Surfacing them in the shared review queue is a lane-1 decision (read `wordtrace.cards`, show a "retrace" prompt linking to `#/words/trace?word=...&script=...`).
- Keyboard / non-pointer alternative: "Show me, stroke by stroke (buttons)". "Next stroke" submits the stroke's own median through the tracer's programmatic `submit()`, so order is taught and drawn on screen. The round is flagged assisted: it never moves the guide forward and never counts as clean. This mode teaches order only; it cannot assess drawing. The vowel step is fully keyboard operable (buttons only).
- Audio: if `ctx.audio.has('word', '<lessonId>-w<n>')` the word is played on finish (lesson words only; nothing is claimed about audio existing).

## Data
- `data/wordtrace/words.json` (generated by `node src/wordtrace/build.mjs`; a test fails if it is stale): 140 two-letter, 220 three-letter, 46 prayer words, plus `lessonLetters` (lesson id -> letters it teaches). Sources: `data/curriculum/lessons.json` (pointing: "course-data"), `data/vocab/words.json` (2-3 letter words; "wiktionary" or "wiktionary-needs-review", reviewed ones first), `prayerwords.json`.
- Caps are 140/220 for vocab words to keep the file small; the lesson and prayer words are all kept.
- The Tetragrammaton (יְהוָה) is excluded on purpose; אֲדֹנָי and אֱלֹהִים/אֱלֹהֵינוּ are in. Teachers may prefer to skip those; there is no per-tradition switch.

## Store keys
`wordtrace.progress` { script: { pointedWord: { done, missed, best, last } } }, `wordtrace.cards` { cardId: srs card }. Reads `letters.progress`, `curriculum.progress`.

## Known limits and doubts
- Stroke data and stroke order are the draft data from `docs/letters/STROKE-RULES.md`; scoring thresholds are untuned on real finger/stylus traces. Word tracing adds no new letter data.
- A word cell is a square sized by the screen (about 175 px at 390 px wide). Letters keep their own per-letter scale, so small letters (yod) look small next to large ones; spacing and relative size inside a real word are not modelled.
- Pointing of vocabulary words comes from Wiktionary-derived data that is flagged `needsReview` for many entries; a wrong pointing would score a correct learner wrong. Not proofread by a native speaker.
- "Blank" rounds score with the stricter no-outline threshold of the tracer.
- Gloss text is English only; the new UI strings are English fallbacks (`t('wt.*')` keys are not in `src/shell/i18n.js`).
- Not checked: screen readers, real touch devices, dark theme of this view, the real app shell (the Playwright check mounts the view in `tests/wordtrace.harness.html`, outside the shell and its router).

## Tests
`node --test` runs `tests/wordtrace.logic.test.js` (bank integrity, sofit, eligibility, niqqud scoring, fade, rating, SRS hook, storage) and `tests/wordtrace.view.test.js` (fake DOM; drives the real tracer with pointer events). `node tests/wordtrace.e2e.mjs` is the Chromium check; screenshots are in `docs/wordtrace/shots/`.
